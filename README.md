# Rambler 7 · Field Voice Unit

A push-to-talk voice recorder for the browser. Hold the bar to speak, release to pause,
and every burst joins one continuous take with the silence between them cut out.
Recordings never leave the device.

Static site, no build step, no dependencies, no framework. One HTML file plus a service worker.

## Deploy

**From the Vercel dashboard**

Push this folder to a Git repo, then import it at vercel.com/new. When asked for a framework,
choose **Other**. Leave the build command and output directory empty. That is the whole setup.

**From the CLI**

```bash
npm i -g vercel
vercel          # preview deployment
vercel --prod   # production
```

## Run locally

The microphone needs a secure context, so `localhost` works but opening the file with a
`file://` path does not give you the service worker (recording itself still works).

```bash
npx serve .
# or
python3 -m http.server 8000
```

## Tests

```bash
cd tests
npm install
npm test
```

340 checks across five suites, run in Node against the real `index.html`:

- **core** — formatting, rename validation, filename sanitising, take numbering, and the
  storage layer against a real IndexedDB implementation. Includes 5 MB round trips,
  60 concurrent writes, a full disk, and a database that never opens.
- **ui** — the actual app driven in jsdom with the capture stack stubbed. Recording,
  saving, renaming, trashing, restoring, deleting, emptying the trash, sharing,
  downloading, crash recovery, interruptions, denied microphone, keyboard operation.
- **layout** — responsive and accessibility rules in the stylesheet.
- **audio** — loudness levelling and 16-bit conversion, then a real encode through the
  bundled encoder, checking the output is a valid mono Layer III file at the right bitrate.
- **deploy** — this configuration: header correctness, manifest accuracy, icon dimensions,
  and that nothing referenced is missing.

## How it works

**Push to talk.** The first hold opens the microphone and starts one `MediaRecorder`.
Releasing calls `pause()`, the next hold calls `resume()`. The recorder closes only when
you press Save, so all bursts land in a single file.

**Nothing is lost.** Each chunk is written to its own IndexedDB record as it arrives.
If the tab dies mid-take, the next launch offers the audio back, reassembled in order.
Audio is stored as `ArrayBuffer` rather than `Blob`, which sidesteps a long-standing
iOS Safari bug with Blobs in IndexedDB. Writes are read back and length-checked, so a
silently failed write reports rather than pretending.

**Level.** Raw microphone input is quiet, especially in hi-fi mode where auto gain is off.
Audio is recorded through a high-pass, makeup gain and limiter chain, so what lands on
disk is already at a usable level. On export it is levelled again against the 99.5th
percentile rather than the absolute peak, so a single cough or knock cannot hold a whole
take down.

**Export format.** Browsers record WebM/Opus, which most phones, chat apps and audio
players refuse to open. Takes are stored in the recorded format so saving is instant,
then converted to MP3 the first time you share or download one, cached for the rest of
the session. Safari records AAC in an `.m4a` already, so that passes through untouched.

**Storage.** Everything lives in the visitor's own browser under the `rambler7` database.
The site has no backend, no analytics and no network calls at all.

## Notes

- Bump `VERSION` in `sw.js` on every content change, or returning visitors keep the old shell.
- Recordings survive redeploys. The service worker cache is separate from IndexedDB and
  clearing it does not touch takes.
- Sharing uses the Web Share API with a real file, so it opens the system sharesheet on
  mobile. Desktop browsers without file sharing fall back to a download.
